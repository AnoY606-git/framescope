# Границы доверия

## Preview target

Разрешённый target — собственный `FrameScope.Demo.exe`. DX использует штатную
загрузку HUD DLL внутри Demo; Vulkan — explicit layer с окружением дочернего
процесса. Это не обещание безопасного внедрения в произвольные игры.
CS2, античиты, kernel hooks и обход защит исключены.

WDDM и advanced Intel providers — только чтение. Не добавляйте setters частот,
power limits или вентиляторов как «исправление» отсутствующей метрики. Нет loader,
domain или доступа — N/A с диагностической причиной, без принудительной установки
драйвера/повышения прав. Driver-provided `ze_loader.dll` не копируется из System32.

## Shared memory и запуск

Случайная 32-hex session уменьшает случайные пересечения, но **не является
криптографической аутентификацией**. Другой процесс того же пользователя может
оказаться в той же границе доверия. Валидируйте header/version, размеры, flags и
числа; не интерпретируйте mapping как доверенный набор указателей. Seqlock решает
согласованность снимка, а не защищает от злонамеренного writer.

Запускайте helpers по явным путям из собственного пакета, не через PATH и не
через shell-конкатенацию пользовательских строк. DLL manifest и native DLL
должны соответствовать одной поставке. Vulkan registry не меняется; родительское
окружение и другие приложения не получают постоянного layer override.

## Данные и диагностика

Профили не должны содержать токены, ключи подписи или memory dumps. Логи могут
раскрывать пути, имя пользователя, процессы и сведения об оборудовании: перед
передачей удаляйте личные данные. Репозиторий и source ZIP не содержат локальные
toolchains, credentials или внутренние материалы разработки.

Проверка policy — ограниченная эвристика, не полный secret scanner и не security
audit. CI не доказывает отсутствие уязвимостей. Сообщение об ошибке безопасности:
[корневой SECURITY.md](../SECURITY.md).
