# Подпись и доверие Windows

Текущие EXE/DLL/installer не заявлены как подписанные доверенным издателем.
SHA-256 проверяет целостность, но не заменяет Authenticode. Debug — конфигурация
разработки, **не исключение из Smart App Control** и не переключатель Developer
Mode Windows. Успех конкретного Debug-файла не гарантирует запуск другого файла
или Release-сборки. SmartScreen и SAC могут принять разные решения; фактические
прогоны описываются отдельно в [VERIFICATION](VERIFICATION.md).

Не отключайте SAC/Defender/SmartScreen, не меняйте security registry и не
импортируйте самоподписанный root ради preview. Самоподписанный сертификат не
делает пакет публично доверенным. Даже валидная подпись не обещает совместимость
с любой корпоративной/локальной политикой.

## Бесплатные законные варианты для индивидуального разработчика

### SignPath Foundation — только после допуска OSS-проекта

Возможен бесплатный signing для принятого Foundation проекта: требуется публичный,
уже выпускаемый OSS, проверяемая сборка из собственных исходников и ручное одобрение.
Нужны соблюдение условий, роли reviewers/approvers и соответствующая policy.
Это не выдача личного сертификата любому владельцу EXE и не автоматическое право
на подписание.

**Сейчас репозиторий private, заявка/одобрение и signing не выполнены.** Видимость
репозитория не меняется автоматически. Если владелец позже сам выберет этот путь,
сначала проверяются [условия Foundation](https://signpath.org/terms), допустимость
проекта и обязательства по исходникам. До одобрения нет badge/утверждений о
предоставленной SignPath подписи. Политики и ограничения могут изменяться.

### Microsoft Store — подпись принятого MSIX, не сертификат для portable/EXE

Для Store-поставки MSIX Microsoft выполняет подпись после прохождения процесса
публикации/сертификации; покупать отдельный сертификат для этого Store MSIX не нужно.
Это **не** личный Authenticode-сертификат для нашего Inno EXE, native DLL или portable
ZIP вне Store. Простое размещение EXE в Store также не заменяет его требования к подписи.

Официальный новый onboarding предлагает бесплатный Individual account через
[Store developer portal](https://storedeveloper.microsoft.com/), но требует ручного
участия владельца и проверки личности. Страна не указана: доступность программы,
поддерживаемые документы/регионы и условия необходимо проверить до подачи.
Руководства: [Individual account](https://learn.microsoft.com/en-us/windows/apps/publish/partner-center/open-a-developer-account),
[MSIX и Store signing](https://learn.microsoft.com/en-us/windows/msix/package/signing-package-overview).
Документы личности передаются только самому официальному сервису, не в Git,
issue или чат проекта.

В проекте пока нет выбранного Store signing/publishing pipeline или MSIX-поставки.
Ничего не зарегистрировано, идентификационные данные не поданы. При выборе Store
потребуются отдельная упаковка, проверка совместимости native helpers/layer и
сертификация; одобрение не обещается.

## Следующий шаг — выбор владельца

При нулевом бюджете выше перечислены варианты с внешними условиями, а не уже
доступная кнопка «подписать». Cloud signer не реализуется до выбора пути и
выполнения предпосылок. Платные signing-сервисы не являются предложенным fallback.
Если signing будет добавлен, подписываются нужные файлы и финальный installer
**до** расчёта окончательных SHA256SUMS, с проверкой издателя, цепочки и timestamp.
Signing keys/credentials не попадают в Git, source archive или CI logs.
